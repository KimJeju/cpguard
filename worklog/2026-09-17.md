# 작업 로그 — 2026-09-17

CPGuard 에 **MCP 서버**를 붙였다. AI 코딩 에이전트(Claude Code·Cursor 등)가 CPGuard 를
도구로 불러 스캔·근거·설명을 받고, 고객 니즈인 **SAST→동적 실증** 루프를 돈다.
MVP 6도구 완성. 설계 → 0~3단계 구현, 각 단계 끝에 실제 stdio E2E 로 확인.

설계 문서: docs/mcp-server-design.md.

## 접근 — B(조준자), A(DAST 엔진) 아님

고객 요구는 "소스 진단에서 나온 취약점을 동적으로 실증". CPGuard 가 HTTP 를 직접 쏘는
DAST 엔진이 되지 않는다. `source→sink→관찰점` 을 아는 것으로 **탐침 + 오라클**을 내주고,
실제 발사는 에이전트가 자기 web 도구로 한다. 근거:

- 해자는 방아쇠가 아니라 조준이다. HTTP 발사는 흔하고 에이전트에 이미 도구가 있다.
- 코어가 소켓을 열면 망분리·외부 무전송 정체성이 무너진다.
- 코드 인텔리전스(파일 읽기·grep·심볼)는 호스트가 더 잘한다 — 안 만든다. 분석이
  필요한 것(findings·evidence·explain·probe·validate)만 낸다.

설계 단계에서 그림을 정직하게 깎았다. 고객이 그린 `dynamic.request.send`·런타임 트레이스
상관(IAST)은 우리가 못 하는 것 — 계측이 없으므로 **오라클 일치**로 간다("실제 실행
경로 확인"이 아니라 "예측한 관찰이 나타났다"). 어제 C/C++ 오탐 0 을 과장 안 한 것과
같은 규율이다.

## 단계별

**0단계 — 걷는 뼈대.** cpguard/mcp/ 패키지 · stdio server.py · 진입점 cpguard-mcp ·
선택 의존성 cpguard[mcp]. cpguard.health 하나만 등록해 배선을 먼저 증명. SDK 없이도
순수 health() 는 돌고 테스트된다.

버그 하나 잡음: 진입점을 gui-scripts 에 뒀더니 Windows 에서 pythonw.exe(콘솔 없음)로
떠 stdio 가 끊긴다. console_scripts 로 이동. mcp 2.x 가 FastMCP→MCPServer 로 개명된
것도 여기서 대응.

**1단계 — 준비 리팩터(동작 0).** 조치 권고·안전 예시 테이블을 pdf.py 에서
report/remediation.py 로 분리. reportlab 을 안 끌어 explain 이 쓸 수 있다. reportlab
import 를 막은 상태에서 remediation_for 가 도는 것으로 확인. 조치맵 테스트 그대로.

**2단계 — 읽기 도구 4개.** render.py(Finding→요약/증거, 안정 id rule:file:line) +
tools.py(FindingStore 세션 저장소). scan_file·finding.list·finding.evidence·explain.
목록은 요약만, 흐름은 요청한 건에만(토큰 예산). E2E: gin 핸들러 → source c.Query →
sink exec.Command 5단계 → 명령주입 조치+안전예시.

**3단계 — 실증 루프(핵심).** probe.py.
- sink 유형(rule_key)별 오라클: cmdi/sqli=time_delay, ssrf=oast_callback,
  xss=reflected_marker, path/file=file_content, redirect=redirect_location. 자동
  오라클 없는 유형은 manual 로 정직하게.
- entry 추출: source 접근자에서 메서드·값 위치·파라미터 이름을 최선값으로. 라우트
  경로는 finding 에 없으므로 항상 에이전트 몫(path=null).
- validation.submit: observed × 오라클 → 4분류. **NOT_REPRODUCED != FALSE_POSITIVE**
  를 행렬 테스트로 박았다. 검증불가 사유(REQUIRES_AUTH 등)는 blocked_reason 으로
  보존해 재현 실패로 뭉개지 않는다.

E2E: scan → probe(command-injection, GET id, `; sleep 5 #`, time_delay) → 지연 관찰
CONFIRMED, 미관찰 NOT_REPRODUCED.

## 배운 것

**설계에서 고객 그림을 정직하게 깎는 것도 설계다.** 30개 도구 비전을 받았지만 절반은
우리 것이 아니었다(호스트가 하는 것) 또는 못 하는 것(IAST). 코드로 가능 여부를 먼저
확인하고(Finding.steps 가 evidence 를 이미 준다·콜그래프는 정방향뿐·런타임 계측 없음)
그 경계 위에서만 약속했다. 스펙에 "못 하는 것"을 명시로 남긴 게 구현을 곧게 했다.

**단계마다 실제 stdio E2E 로 배선을 증명했다.** 단위 테스트는 in-process 라 전송을
안 탄다. gui-scripts 버그는 E2E 아니면 못 잡았다.

## 남은 것 (MVP 이후)

- scan_start/scan_status — 리포 전체 비동기 감사(jobs.py).
- verify — 고친 뒤 전후 대조(직전 스캔 결과 보관).
- callers — 콜그래프 역엣지 구축 후.
- 라우트 힌트 강화 — 지금은 메서드·param 만, 경로는 에이전트 몫.
- 저장소 정책의 실앱 비용 확인(DVWA).
