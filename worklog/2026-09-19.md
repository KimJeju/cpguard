## Java 벤치 project vs file 모드 — 기본은 project 유지

전날 벤치 러너가 느려 `--mode file`(파일 단위 전 단계 병렬, 300건 8초)로 바꿀 수
있는지 같은 300건으로 쟀다(데이터 흐름 5배 개선 후 project 300 = 8분 59초 · 전체
2,740 트리를 스캔하므로 `--limit` 이 스캔 범위를 줄이지 않는다).

| 300건 | 재현율 | 정밀도 | 오탐률 | 점수 | TP/FN/FP |
|---|---:|---:|---:|---:|---|
| project | 93.8% | 91.9% | 15.1% | 0.787 | 91 / 6 / 8 |
| file | 90.7% | 91.7% | 15.1% | 0.756 | 88 / 9 / 8 |

차이는 pathtraver·sqli·xss 각 TP +1 — `org.owasp.benchmark.helpers.*` 를 거치는
파일 경계 흐름이고 FP 는 같다. **정확도 기록은 project, 규칙 만지며 신호 볼 때만 file.**
러너의 project 모드가 `--limit` 과 무관하게 전체 트리를 스캔하는 것은 그대로 둔다 —
헬퍼가 어느 파일에 있을지 모르므로 부분 트리 스캔은 곧 file 모드와 같은 손실이다.
