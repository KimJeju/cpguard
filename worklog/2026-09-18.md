# 작업 로그 — 2026-09-18

## GUI 스캔 파싱 병렬 기본값 (1 → auto)

웹/데스크톱 GUI 스캔이 항상 단일 프로세스로 파싱하고 있었다. `views.py` 의 스캔 잡이
`CPGUARD_JOBS` 환경변수로만 워커 수를 받고 기본값이 `"1"` 이라, GUI 에는 워커 입력칸이
없으니 사실상 병렬을 켤 방법이 없었다(env 를 알고 미리 박아야만 했다).

기본값을 `min(os.cpu_count() or 1, 8)` 로 바꿨다. env 로 여전히 오버라이드 가능
(`CPGUARD_JOBS=N`). GUI 입력칸은 만들지 않았다 — 좋은 auto 기본값이면 대부분 유저는
env 도 필드도 안 건드리고, 튜닝 수요가 실제로 생기면 그때 넣는다.

- 8 캡: `scan_path` 의 jobs 는 **파싱 단계만** 병렬화한다(taint/함수요약 분석은 순차).
  코어를 그 이상 줘도 파싱 이득은 프로세스 스폰 오버헤드에 먹힌다.
- frozen exe 안전: 진입점에 `multiprocessing.freeze_support()` 이미 적용돼 있다
  (scanner.py docstring 명시).

변경: `cpguard/web/views.py:249`.

## 벤치마크 러너 성능 메모 (코드 변경 아님)

자바 OWASP 벤치가 느린 원인을 확인했다. `bench/owasp_benchmark.py` 기본이
`--mode project` + `--workers` 미지정 → `_scan_project` 가 `scan_path(jobs=1)` 로
단일 프로세스. project 모드는 전체 코퍼스에 파일간 함수요약을 붙여 가장 무거운 조합이다.

- 최소 조치: `--workers 8`. project 모드도 workers 를 `scan_path(jobs=)` 로 넘긴다
  (파싱만 병렬이라 sub-linear).
- 큰 레버: `--mode file` (파일 단위 ProcessPoolExecutor, 전 단계 병렬). 단 OWASP Java 는
  `org.owasp.benchmark.helpers.*` 를 거치는 흐름이 있어 파일 모드면 재현율이 떨어질 수
  있다 → `--limit 300` 으로 project vs file 재현율 먼저 비교하고 결정.
- 개발 루프에선 `--limit` 로 빠르게, 전량은 수치 기록할 때만.

## C# CWE-89 재현율 대개편 (12.7% → 79.5%)

C# 전체 점수(0.245)의 발목이던 CWE-89(코퍼스 64%, 재현율 12.7%)를 재현으로 근본원인
두 개를 특정해 고쳤다. SARD C# 스위트를 최소재현으로 프로브(b1~b3·r1~r3)해 격리했다.

**버그 B — `cmd.CommandText = <오염>` 대입 싱크 미인식 (커밋 1b96158)**
- 스위트는 전부 `CreateCommand → cmd.CommandText = query → cmd.Execute*()` 체인.
  규칙이 CommandText 를 call 싱크로만 둬서 대입 형태를 통째로 놓쳤다.
- `_check_sinks` 는 호출식만 검사한다(engine.py:722). 대입문(`ir.Assign`) 핸들러는
  RHS 만 싱크 검사하고 target 은 안 봤다.
- 수정: `SinkPattern` 에 `kind='assign'` + `property` 추가, `_check_assign_sink` 로
  `obj.Prop = 오염` 검사. 상수 CommandText(파라미터라이즈드)는 RHS 가 안 오염돼
  안 걸린다 → 정밀도 유지.

**버그 A — `Main(string[] args)` 명령행 인자 소스 미인식 (커밋 b2b5c25)**
- 코퍼스 CWE-89 의 1/4 이 `args[i]` 소스. 소스 목록에 없어 통째 미탐.
- `args[i]` 는 path_of 가 `'args.i'` 를 준다 → name 소스 `args` 가
  `startswith('args.')` 로 잡는다. 엔진 수정 없이 규칙 1줄.
- ponytail: 1줄 먼저 넣고 정밀도를 측정해 무너지지 않는 것을 확인한 뒤 채택
  (Main 게이트 같은 방어는 필요 없었다). 안전(prepared) 버킷 전 소스 0% = FP 없음.

**측정 (정본 manifest state 라벨, CWE-89 랜덤 1500 표본)**

- 구성별: args 0→78~86%, readline 0→78~80%, shell 0→68~74%, hardcoded 0%(상수라

- CWE-89 가 C# 코퍼스 64% → 전체 C# 점수 0.245 → ~0.5 대 예상.
