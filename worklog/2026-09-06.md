## 1. 제외 경로 판정 (`57d5b2d`)

`_excluded()` 가 절대경로의 **모든** 파트를 제외 목록과 대조했다. 그래서 스캔 루트
'바깥'의 조상 디렉터리 이름이 걸려도 파일을 버렸다.

리눅스에서 업로드본을 `/tmp` 에 풀면 `tmp` 가 걸려 **프로젝트 전체가 스캔되지 않았고**,
그런데도 결과는 "탐지 0건"으로 나왔다. 무결성 보고(`ScanReport`)에도 남지 않았으니,
0건이 안전을 뜻하는지 못 읽어서인지 구분하려고 만든 장치를 이 버그가 그대로 배신한 셈이다.
윈도우는 임시 폴더가 `Temp` 라 대소문자가 달라 걸리지 않았다 — 개발 환경에서만 초록불.

수정: `p.relative_to(root).parts` 만 검사. 루트 안쪽의 `node_modules`·`build` 는 그대로 제외된다.
회귀 테스트는 `tmp/build/proj` 밑에 프로젝트를 만들어 스캔한다(수정 전 코드에서 실패 확인).

## 2. 한글 폰트 (`a6d25df`)

리눅스 서버에는 한글 폰트가 기본 설치되지 않는다. reportlab 이 Helvetica 로 폴백해
**본문이 전부 `■` 인 PDF** 를 만들었다. HTTP 200, 파일도 정상적으로 열리기 때문에
발주처에 전달되기 전까지 아무도 모른다.

- **나눔고딕(OFL-1.1) 동봉** — `cpguard/report/fonts/`. 탐색 순서의 **최후 보루**로 넣어
  시스템 폰트가 있으면 그쪽이 우선한다(기존 산출물 모양 불변).
- 배포 경로 3곳 모두 연결: 휠 `package-data`, PyInstaller `spec` datas, 라이선스 전문 동봉 + README 고지.
- 동봉본까지 못 읽으면 `KoreanFontMissing` 으로 **중단**. 깨진 문서를 만드는 것보다 낫다.
  영문 산출물은 Helvetica 로 계속 생성된다.

## 3. SARIF 줄번호 (`96c9c32`)

GitHub Code Scanning 이 업로드를 거부하고 있었다.

```
instance.runs[0].results[63].locations[0].physicalLocation.region.startLine
must be greater than or equal to 1
```

파일명 규칙(`secret.risky-filename` — `.env`·`id_rsa`·`*.pem`)은 줄이 없어 `Loc(start_line=0)`
으로 만든다. 설계상 맞는 값이지만 SARIF 는 1-based 다. 그리고 GitHub 은 **결함 하나에
파일 전체를 반려**하므로, 이 규칙이 들어간 이후 모든 CI 실행이 결과를 한 건도 올리지 못했다.
스캔 단계는 매번 성공해서 로그로는 보이지 않았다.

수정은 규칙이 아니라 직렬화 한 곳에서 — `_location()` 에서 `max(1, line)`, `endLine >= startLine`.
0을 만드는 다른 규칙이 생겨도 같은 참사가 나지 않는다.

> 진단법 메모: 실패 원문은 `GET /repos/{owner}/{repo}/check-runs/{job_id}/annotations` 에 있다.
> 로그 API 는 인증이 필요하지만 이쪽은 공개 저장소면 그냥 읽힌다.

## 4. CI (`907f407`)

워크플로가 자기 자신을 스캔하기만 하고 **테스트 잡이 없었다.** 위 세 건이 전부 손으로
리눅스를 돌려서 나온 것이라 자동화가 필요했다.

`ubuntu-latest` + Python 3.12 + `pip install -e '.[dev]'` + `pytest -q`.
러너에 **한글 폰트를 일부러 깔지 않는다** — 맨 러너가 동봉 폰트의 회귀 테스트 역할을 한다.
(`'.[dev]'` 따옴표 필수, bash 가 `[dev]` 를 글롭으로 본다.)

부수적으로 `pypdf` 가 dev extra 에 없던 것도 드러났다. 테스트 5개가 임포트하는데 윈도우
환경에 수동 설치돼 있어 안 보이던 구멍이다.

## 5. 코드 정리 (`a3cfdc4`)

- `cpguard/generated.py` **삭제** — 자동생성 코드 제외 기능이 구현·테스트까지 끝났는데
  제품 코드 어디서도 import 하지 않았다. 호출부가 생길 때 되살린다. (-138줄)
- 수동 카운팅 17곳 → `collections.Counter`. `sorted(items, key=lambda x: -x[1])[:N]` 이
  `.most_common(N)` 이 된다.
- **함정**: `Scan.severity_counts` 를 Counter 그대로 반환했더니 테스트 30개가 깨졌다.
  Django 템플릿은 `{{ d.items }}` 를 `d["items"]` 로 **먼저** 조회하는데 Counter 는
  없는 키에 `0` 을 돌려주므로 `{% for %}` 가 int 를 순회하려 든다. 템플릿에 나가는
  프로퍼티만 `dict()` 로 감쌌다(이유는 주석으로 남김).

## 6. 벤치마크 (`cae5d76`)

커밋된 `bench/owasp_result.json` 이 README 뱃지보다 한 커밋 뒤처져 있었다(F1 0.617 vs 0.689).
재실행 결과 문서 수치와 정확히 일치 — TP 533 / FN 286 / FP 195 / TN 558, F1 **0.689**, 점수 **0.392**.

`UnicodeEncodeError` 로 죽으면 몇 분 돌린 결과가 통째로 날아간다(실제로 겪음).

## 7. 릴리스 0.1.4 (`f5d61ac`, `2790bd4`)

동봉 폰트·exclude·SARIF 수정으로 **패키지 내용물이 바뀌었는데** 0.1.3 설치본이 이미
배포돼 있어 버전을 올렸다(`pyproject.toml` + `cpguard.iss`).

빌드하며 스크립트 함정 2건:

- `build.ps1` 이 `python` 을 그냥 호출 → conda 프로필이 셸을 base 환경으로 되돌려
  **의존성 없는 인터프리터로 빌드가 시작**됐다. `$CPGUARD_PYTHON` 으로 지정 가능하게.
- 마지막 안내 줄이 `Select-Object -First 1`(이름순)이라 릴리스가 쌓인 뒤로는
  **항상 `CPGuard-Setup-0.1.0.exe`** 를 가리켰다. 0.1.4 를 만들어놓고 0.1.0 을 만들었다고
  출력했다. `LastWriteTime` 정렬로 수정.

산출물: `packaging/output/CPGuard-Setup-0.1.4.exe` (49.6MB, 0.1.3 대비 +0.9MB).
`dist/CPGuard/_internal/cpguard/report/fonts/` 에 폰트 반영 확인, 설치본으로 한글 PDF 출력 실물 확인.
