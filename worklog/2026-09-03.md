## 3. 테마 4종·스크롤바·소스 트리 (`32794a6`)

- **테마 4종** — 다크(기본)/라이트/VS Code/Ghidra(회색). 헤더 셀렉터, 루트 `data-theme` +
  `localStorage` 영속, `<head>` 인라인 스크립트로 FOUC 방지.
  모든 템플릿(workbench/base/project_home/index)의 하드코딩 색을 CSS 변수로 치환.
  배지·코드 하이라이트 틴트는 `color-mix()`로 accent/severity에서 파생 →
  테마 추가 시 `[data-theme="x"]` 블록에서 변수만 재정의하면 됨.
- **스크롤바** — VS Code식 얇은 오버레이(패딩 있는 thumb, 호버 시 진해짐). 테마 변수로 색.
  `scrollbar-width:thin` + `::-webkit-scrollbar` 병행.
- **소스 트리** — 좌측 패널에 `소스` 뷰 추가(목록/표/소스 토글). 폴더 접힘, 파일별 위험도 점·건수,
  클릭 시 첫 이슈 조사 또는 원본 열기.

검증: 4개 테마 전부 브라우저 스크린샷 확인, 콘솔 에러 0, 팔레트/컨텍스트 메뉴/툴팁 테마 전환 후에도 정상.
참고: `color-mix()`는 최신 크로미움/파이어폭스(2023+) 필요.

## 4. install → run 검증 + CLI 버그픽스 (`43ad4bf`)

클린 venv(Python 3.11)에 `pip install .` → 휠 빌드·전 의존성 해결 성공.

- **발견한 버그**: `cpguard scan`이 규칙 메시지의 em-dash(`—`)를 한글 Windows 콘솔(cp949)에
  출력하다 `UnicodeEncodeError`로 크래시.
- **근본 수정**: CLI 진입점에서 stdout/stderr를 utf-8로 재설정(`_force_utf8_output`).
  리다이렉트·캡처 스트림이면 무시. 특정 문자가 아니라 인코딩이 원인이므로 모든 출력에 적용.
- 재실행 시 7건 정상 출력 + SARIF(스키마 유효)·분석목록표 xlsx 저장 확인.
- CLI 스모크 테스트 3개 추가(`tests/test_cli.py`).
- 대시보드 `cpguard serve` 200, 실행 중 대시보드에 zip 업로드→스캔→작업대 렌더까지 실측.

## 5. 클린/오프라인 머신 대응

내부망·에어갭·세팅 안 된 클린 머신 배포 요건. 답은 **PyInstaller onedir + Inno Setup exe**
(파이썬·pip·인터넷 불필요, 전부 exe 번들).

### 5-1. frozen 번들 자기완결성 실증

- 기존 `dist`·설치본은 9/2 빌드라 오늘 UI 미포함, 게다가 그 번들엔 tree_sitter_python이 빠져 있었음
  (당시 Python 어댑터 전). 최신 코드로 재빌드.
- 외부 파이썬 없이 frozen `CPGuard.exe` 실행 → 내부 django 서버 자동 기동(랜덤 포트) →
  웹뷰 창 → 대시보드 200 → zip 업로드→스캔(번들 tree-sitter 네이티브로 7건 탐지) →
  작업대 테마·소스트리 렌더 확인.

### 5-2. 브라우저 폴백 (`1d112b9`)

`cpguard/desktop.py` — 네이티브 창(pywebview/WebView2) 생성 실패 시 치명 오류로 보지 않고
기본 브라우저로 대시보드를 열고 서버를 살려둠. webview 미탑재·런타임 부재 양쪽 처리.
데스크톱 런처 테스트 추가(`tests/test_desktop.py`).
frozen exe에서 webview 백엔드 강제 실패시켜 폴백 경로 실측(서버 생존·브라우저 열림·200).

### 5-3. WebView2 런타임 전제조건 동봉 (`b5216cd`)

네이티브 창을 클린 머신에서도 보장하기 위해 설치본에 WebView2 설치기를 동봉.

- `packaging/cpguard.iss` — 레지스트리로 런타임 존재 확인(per-machine `WOW6432Node`·per-user),
  없을 때만 앱 실행 전 `/silent /install`(관리자 없이 per-user 설치), 있으면 건너뜀.
- `packaging/build.ps1` — 부트스트래퍼 자동 확보. 에어갭 배포는 오프라인 단독 설치기
  (`MicrosoftEdgeWebView2RuntimeInstallerX64.exe`, ~130MB)를 `packaging/redist/`에 두면 우선 사용.
- `.gitignore` — `packaging/redist/` 추가(런타임 바이너리는 미커밋).
- 검증: Inno 컴파일 성공, WebView2 설치기 동봉 확인(설치본 20.8MB → 22.4MB).
  실제 "부재→자동설치" 경로는 WebView2 있는 이 머신에선 실물 테스트 불가 →
  WebView2 없는 클린 VM에서 확인 필요.

### 산출물 (git 미추적, 빌드 산출물)

- `dist/CPGuard/CPGuard.exe` — 무설치 이동식(폴더 통째 68MB)
- `packaging/output/CPGuard-Setup-0.1.0.exe` — 설치본 22.4MB, 사용자 영역 설치(관리자 불필요)

## 부록: VirtualBox VM 복구 (CPGuard 무관, 세션 중 처리)

CPGuard 테스트용 VM(`windows_10`)이 스냅샷 차분디스크 소실로 부팅 불가(`VERR_FILE_NOT_FOUND`)였음.

- 원인: `Snapshots/` 폴더의 차분디스크 3개와 `.sav` 상태파일 삭제됨. base `windows_10.vdi`(13.4GB)만 생존.
- 복구: 깨진 VM을 `--delete` 없이 등록 해제(파일 보존) → 원본 스펙(RAM 8192, CPU 2, VRAM 128,
  BIOS, NAT)대로 새 VM `windows_10_recovered` 생성 → base vdi 부팅 디스크로 연결 →
  헤드리스 부팅으로 medium 에러 해소 확인 후 종료.
- 상태: base(2026-06-19 `init_windows` 스냅샷) 시점으로 복구. 그 이후 변경분은 소실(불가피).
  VirtualBox 관리자에서 `windows_10_recovered` 실행. 네트워크는 NAT로 세팅됨(특수 구성 필요 시 재조정).
