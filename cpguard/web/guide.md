# CPGuard 사용 가이드

소스코드를 올리면 취약점을 찾아 위험도별로 정리하고, 코드 위에서 데이터 흐름을 따라가며
조사·판정하고, 발주처 제출용 산출물까지 만드는 도구입니다.

**처음이라면 1절만 따라 하면 됩니다.** 나머지는 필요할 때 찾아보는 참조입니다.

---

## 1. 5분 만에 첫 진단

1. **홈** 에서 소스 프로젝트를 **zip** 으로 올립니다. 여러 개를 한 번에 골라도 되고,
   프로젝트 zip 들을 담은 zip 하나를 올려도 각각 진단합니다(배치 진단).
2. 필요하면 아래 옵션을 켭니다. **아무것도 안 켜도 됩니다.**
3. **진단 시작** → 진행 화면에서 단계별 진행 바와 로그를 봅니다. 중간에 **중단**할 수 있습니다.
4. 끝나면 **프로젝트로 이동** → 결과를 봅니다.

업로드 화면의 선택 항목:

| 항목 | 언제 켜나 |
|---|---|
| **점검 기준** | 행안부 개발보안 가이드·전자금융감독규정 등 어떤 점검표로 묶어 보고할지. 나중에 검토 화면에서 바꿔도 됩니다 |
| **시크릿·설정만 빠르게** | 비밀정보·설정만 급히 볼 때. 데이터 흐름 분석을 생략해 훨씬 빠릅니다 |
| **LLM 트리아지** | 오탐을 줄이고 싶을 때(7절). API 키가 있어야 합니다 |
| **오픈소스 컴포넌트(SCA)** | 쓰고 있는 라이브러리의 알려진 취약점을 볼 때(8절) |

> 큰 프로젝트(수만 파일·수 GB)도 됩니다. 수 분 걸리는 것이 정상입니다.

## 2. 화면 구성 한눈에

| 화면 | 무엇을 하는 곳 |
|---|---|

| **취약점 검토** (`자세히`) | 3분할로 한 건씩 조사·판정하는 주 작업 화면 (4절) |

| **설정** `/settings/` | LLM API 키 · 보고서 양식 |

## 3. 무엇을 찾나

세 축으로 봅니다.

**① 데이터 흐름 (taint)** — 사용자 입력(source)이 위험한 지점(sink)까지 흘러가는지 추적합니다.
함수 경계를 넘어가고(프로시저 간), 분기가 상수로 정해지면 죽은 가지를 접습니다.

- SQL 주입(CWE-89) · 명령 주입(78) · 코드 주입(94) · XSS(79) · 경로 조작(22) ·
  파일 포함(98) · SSRF(918) · 오픈 리다이렉트(601) · 역직렬화(502) ·
  LDAP 주입(90) · XPath 주입(643) · 버퍼 오버플로(120) · 포맷 스트링(134) ·
  라이브러리 주입(114) · Intent 리다이렉션(926)
- Java · Kotlin · C# · JavaScript · TypeScript · Python · PHP · Go · Ruby · Swift · C/C++

**② 패턴 (단일 지점)** — 전 언어 + 설정 파일(.env·.yml·.properties·.xml·SQL 덤프).

- 하드코딩 비밀정보(798)·벤더 API 키 · 개인정보(PII) · TLS 검증 비활성(295) ·
  취약 해시/암호(327) · 하드코딩 암호키(321) · 예측 가능 난수(338) · 쿠키 플래그(1004) ·
  디버그 코드(489) · 인프라 설정

**③ 오픈소스 컴포넌트 (SCA)** — 잠금파일을 읽어 알려진 취약점(CVE)을 조회합니다(8절).

## 4. 취약점 검토 화면

3분할입니다. 좌우 패널은 가운데 구분선을 끌어 넓힐 수 있고, 상단 버튼으로 접을 수 있습니다.

### 좌: 이슈 탐색기

- **보기 전환** — `목록` / `표`(정렬 가능) / `소스`(파일 트리)
- **그룹** — 유사 이슈 그룹 · 위험도별 · 규칙별 · 파일별 · 유형별 · 점검항목별
- **필터** — 검색어 · 위험도 · 유형 · 신규만/오탐힌트만/흐름 불확실만 · 감사 상태 · 점검 기준
- **흐름 내용 필터** — 추적 경로 *안의 코드*로 거릅니다. `/정규식/` 도 됩니다.
  예: `sanitize` 를 `미포함`으로 두면 정제를 거치지 않은 흐름만 남습니다.
  구간을 `전체 흐름` / `발생 원인(source)` / `발생 지점(sink)` 으로 좁힐 수 있습니다.
- **감사 완료 숨기기** — 판정 끝난 건을 목록에서 뺍니다.
- **체크박스** — 행 왼쪽. 체크한 것만 일괄 판정할 수 있습니다(5절).

### 중앙: 코드 뷰어

취약 코드를 원문 위에 보여 줍니다. source→sink 흐름이 색으로 강조되고, 같은 파일의 다른
이슈 위치는 왼쪽 여백에 표시됩니다(눌러서 이동). `경로 복사` · `줄 이동` 버튼이 있습니다.

### 우: 인스펙터

- **위험도 · 규칙 · CWE · OWASP · 위치 · 신뢰도 · 탐지값**(마스킹) · **설명**
- **정확도 — `흐름 불확실`** 배지: 이 흐름이 *분석 대상에 코드가 없는 함수*를 지났다는 뜻입니다.
  그 함수 안에서 정제됐다면 오탐입니다. **이 배지가 붙은 것부터 확인하면 검토가 빨라집니다.**
- **데이터 흐름 (N단계)** — 단계를 누르면 그 줄로 이동합니다.
- **판정 버튼** · **감사자 의견** · **판정 이력**

### 하단: 분석 패널

흐름 시각화 · AI 분석(자유 질문) · 로그. 상단 `분석 패널` 버튼으로 접습니다.

### 키보드

| 키 | 동작 |
|---|---|
| `j` / `k` (또는 ↑↓) | 다음 / 이전 이슈 |
| `n` / `p` | 흐름의 다음 / 이전 단계 |
| `q` `w` `e` `r` | 취약 확정 · 오탐 · 조치완료 · 보류 |
| `Enter` | AI 에게 설명 요청 |
| `Ctrl+P` | 커맨드 팔레트 — 규칙·파일·CWE 로 이동 |
| `Esc` | 하단 패널 접기/펼치기 |

> 판정 단축키는 **한글 입력 상태에서도 그대로 동작**합니다(물리 키 위치로 읽습니다).

## 5. 판정하고 근거 남기기

판정은 다섯 가지입니다. **미확인 / 취약 확정 / 오탐 / 조치완료 / 보류**.
`오탐`·`보류`·`조치완료` 로 판정하면 상단 **조치대상** 숫자가 즉시 줄어듭니다.

**한 건씩** — 인스펙터의 판정 버튼 또는 `q`/`w`/`e`/`r`.
`판정 후 다음 이슈로` 를 켜 두면 판정과 동시에 다음 건으로 넘어갑니다. 100건을 연속으로
넘길 때 클릭 수가 절반이 됩니다.

**여러 건 한 번에** — 좌측 하단 `일괄 판정…` 에서 판정을 고르고 `적용`.

- 행 체크박스로 **고른 것만** 대상이 됩니다. 하나도 안 고르면 **지금 목록에 보이는 전부**가 대상입니다.
- 확인 창에서 **감사자 의견**을 함께 적을 수 있고, 대상 전체에 같은 내용으로 저장됩니다.
- 이미 의견이 적힌 건이 섞여 있으면 그 건수를 알려 주고, **기본은 덮어쓰지 않습니다.**

**근거 남기기** — `감사자 의견` 에 판단 근거를 적습니다. 발주처 검수에서 "이 오탐 판정
누가 왜"를 물으면 근거가 있어야 합니다. **판정 이력** 에 변경 기록이 시각과 함께 남습니다.

**재진단 판정 승계** — 같은 프로젝트를 다시 스캔하면, 지문이 같은 이슈의 지난 판정·의견을
그대로 가져옵니다. 목록에 `지문이 같은 이슈의 지난 판정·의견을 그대로 가져왔습니다` 로 표시됩니다.

## 6. 점검 기준과 제외 설정

**점검 기준** — 결과를 어떤 점검표로 묶어 보고할지 정합니다. 스캔은 기준과 무관하게
한 번만 돌고, 기준은 나중에 바꿔도 됩니다.

- 행정안전부 소프트웨어 개발보안 가이드 · 보안설계 기준(설계단계)
- 모바일 대응 보안약점 진단 · 전자금융감독규정 웹 취약점 · OWASP Top 10 · CWE

**제외 설정** (프로젝트 홈) — 진단 대상에서 뺄 것을 프로젝트별로 저장합니다.

- **제외 경로** — 한 줄에 하나, glob. 예: `tests/**`, `vendor/**`
- **제외 규칙** — 한 줄에 하나, 규칙 id
- **제외 사유** — 보고서의 `제외 정보` 절에 그대로 실립니다

> 무엇을 왜 뺐는지가 산출물에 남습니다. 조용히 빼면 "0건"이 안전인지 안 본 건지 구분되지 않습니다.

## 7. LLM 트리아지 (선택)

오탐을 줄이려면 LLM 으로 각 이슈의 도달 가능성을 재검증할 수 있습니다.

1. **설정 · LLM** 에서 Claude / Gemini / ChatGPT 중 하나의 **API 키** 를 넣습니다.
   각 프로바이더의 `발급 가이드` 버튼에 키 얻는 방법이 있습니다.
2. 업로드 화면에서 `LLM 트리아지로 오탐 재검증` 을 체크하고 프로바이더·모델을 고릅니다.
3. 검토 화면의 **AI 분석** 패널에서 개별 이슈를 따로 질의할 수도 있습니다.
   예: "이 정제가 우회 가능한가?"

- 키는 이 PC 의 `~/.cpguard/config.json` 에만 저장되고 외부로 전송되지 않습니다.
- **Gemini** 는 무료 티어가 있어 처음 시험하기 좋습니다.
- Claude 키에서 `anthropic-workspace-id is required` 오류가 나면 설정의
  **워크스페이스 ID** 칸을 채우세요.

## 8. 오픈소스 컴포넌트 (SCA)

잠금파일을 읽어 컴포넌트 목록을 만들고, 알려진 취약점(CVE)을 조회합니다.

**읽는 잠금파일** — `requirements.txt`(`==` 고정만) · `package-lock.json` · `pom.xml` ·
`go.mod` · `Gemfile.lock` · `composer.lock` · `packages.config`

**기본은 꺼져 있습니다.** 조회하면 패키지 이름·버전이 OSV.dev 로 나갑니다. 의존성 목록은
그 자체로 정보라, 사용자가 명시할 때만 나갑니다.

### 망분리 환경에서 쓰기

인터넷 되는 곳에서 스냅샷을 미리 받아 옮기면 **네트워크 없이** 조회할 수 있습니다.

```bash
cpguard osv-sync --dir D:\osv                          # 인터넷 되는 곳에서
cpguard scan <경로> --sca --sca-db D:\osv              # 망분리 환경에서
```

환경변수 `CPGUARD_OSV_DIR` 로 지정하면 웹 화면에서도 그 스냅샷을 씁니다.
**스냅샷이 있으면 네트워크보다 먼저 씁니다** — 의존성 목록이 밖으로 나가지 않습니다.

> **"취약점 없음"과 "조회 못 함"은 다릅니다.** 조회가 막힌 환경에서는 `미수행` 으로
> 보고합니다. 확인하지 않은 것을 "없음"으로 적지 않습니다.

**부산물: SBOM** — 취약점이 없어도 컴포넌트 목록은 나옵니다. 보고서 **부록 E** 에
생태계·이름·버전·라이선스로 실립니다. 라이선스는 잠금파일이 값을 들고 있는
npm·composer 만 채워집니다.

## 10. 규칙 조정

동봉 규칙을 고치지 않고 **덮어쓰기 파일**로 조정합니다. 소스 수정이 필요 없습니다.

- 위치: `~/.cpguard/specs/*.yml` (환경변수 `CPGUARD_SPECS` 로 변경 가능)
- 같은 `id` 의 yml 을 두면 동봉 규칙 **위에 겹쳐집니다.**
- 리스트 항목(`sinks`·`sanitizers`·`validators`)은 **이어붙고**, `severity` 같은 값은 덮어씁니다.
- 동봉 목록을 통째로 버리려면 `replace: true`.

쓰는 곳:

- 사내 검증 함수를 **정제(sanitizer)** 로 인정시키기
- 사내 프레임워크의 위험 함수를 **sink** 로 추가하기
- 특정 규칙의 **severity 를 내리기**

조정한 규칙이 있으면 보고서의 **수행 조건**에 그 사실이 남습니다.

라이브러리 함수의 동작 선언(`~/.cpguard/summaries/*.yml`)도 같은 방식입니다.
`block`(오염이 끊김) / `propagate`(그대로 흐름)를 선언하면 `흐름 불확실` 표시가 줄어듭니다.

## 11. CLI · CI/CD

```bash
cpguard scan <경로>                          # 기본 스캔
cpguard scan <경로> --sarif out.sarif        # SARIF 로 저장
cpguard scan <경로> --fail-on high           # high 이상이면 종료코드 1 (CI 게이트)
cpguard scan <경로> --sca --sca-db D:\osv    # 오프라인 SCA 포함
cpguard serve                                # 웹 대시보드
cpguard app                                  # 독립 데스크톱 창
```

GitHub Actions:

```yaml
- uses: KimJeju/cpguard@v0.1.3
  with: { path: '.', fail-on: 'high' }
- if: always()
  uses: github/codeql-action/upload-sarif@v3
  with: { sarif_file: '${{ steps.<id>.outputs.sarif }}' }
```

## 12. 자주 묻는 것

**인터넷 없이 되나요?**
