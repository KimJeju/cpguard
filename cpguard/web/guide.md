# CPGuard 사용 가이드

CPG 기반 taint 분석 + LLM 트리아지를 결합한 정적 보안 분석(SAST) 도구입니다.
소스코드를 올리면 취약점을 찾아 위험도별로 정리하고, 코드 위에서 데이터 흐름을 따라가며
조사·판정할 수 있습니다. 이 문서는 처음 쓰는 분을 위한 5분 안내입니다.

## 1. 무엇을 찾나요

두 축으로 탐지합니다.

- **데이터 흐름(taint)** — 사용자 입력(source)이 위험한 지점(sink)까지 흘러가는지 추적합니다.
  SQL 주입(CWE-89) · 명령 주입(78) · 코드 주입(94) · XSS(79) · 경로 조작(22) · 파일 포함(98) ·
  SSRF(918) · 오픈 리다이렉트(601). 지원 언어: JavaScript · TypeScript · PHP · Python.
- **패턴(단일 지점)** — 전 언어 대상. 하드코딩 비밀정보·API 키 · 개인정보(PII) ·
  TLS 검증 비활성 · 취약 암호/해시 · 디버그 코드 · 설정 위생.

## 2. 첫 진단 (3단계)

1. **홈** 화면의 **프로젝트 업로드** 에서 소스 프로젝트를 **zip** 으로 올립니다. 큰 프로젝트(수만 파일, 수 GB)도 됩니다. 압축을 풀며 안전성을 검사합니다.
2. **진단 시작** → 진행 화면에서 단계별 진행 바와 로그를 확인합니다.
3. 완료되면 **프로젝트로 이동** 을 눌러 결과를 봅니다.

비밀정보·설정만 빠르게 보려면 업로드 화면에서 **`시크릿·설정만 빠르게`** 를 체크하세요(데이터 흐름 축 생략).

## 3. 결과 읽기

### 프로젝트 홈
- **보안 상태** — 총 탐지 수와 위험도 분포. 위험도 배지를 누르면 아래 **취약점 탐색기** 에서
  해당 위험도만 필터링됩니다.
- **취약점 탐색기** — 위험도 도넛·상위 규칙/CWE 그래프 + 전체 목록. 위험도·규칙·종류로
  필터링하고 페이지네이션으로 전부 훑을 수 있습니다. 규칙 막대를 누르면 그 규칙만 봅니다.
- **위험도 추세** — 같은 프로젝트를 다시 스캔하면 스캔 간 신규/해결이 비교됩니다.

### 감사 작업대 (`자세히`)
3분할 화면으로 한 건씩 조사합니다.

- **좌: 이슈 탐색기** — 목록/표/소스 트리. 규칙·파일·위험도로 그룹·필터.
- **중앙: 코드 뷰어** — 취약 코드를 원문 위에 표시. source→sink 흐름이 색으로 강조됩니다.
- **우: 인스펙터** — 규칙·CWE·OWASP·데이터 흐름 단계·LLM 판정.
  - **판정 버튼**(미확인/취약 확정/오탐/조치완료/보류)으로 사람이 최종 판정합니다.
  - **감사자 의견** 칸에 판단 근거를 적고 저장할 수 있습니다.

> **무결성 원칙** — "0건"이 안전인지 못 읽은 건지 구분합니다. 파싱 실패·크기 초과·구문오류는
> 상단 **스캔 무결성** 줄에 그대로 표시됩니다. 도구가 취약점을 조용히 숨기지 않습니다.

## 4. LLM 트리아지 (선택)

오탐을 줄이려면 LLM 으로 각 이슈의 도달 가능성을 재검증할 수 있습니다.

1. **⚙️ 설정 · LLM** 에서 Claude / Gemini / ChatGPT 중 하나의 **API 키** 를 넣습니다.
   각 프로바이더 **`발급 가이드`** 버튼에 키 얻는 방법이 있습니다.
2. 업로드 화면에서 **`LLM 트리아지로 오탐 재검증`** 을 체크하고 프로바이더·모델을 고릅니다.
3. 작업대의 **AI 분석** 패널에서 개별 이슈를 질의할 수도 있습니다("왜 취약한가", "악용 가능성" 등).

- 키는 이 PC 의 `~/.cpguard/config.json` 에만 저장되고 외부로 전송되지 않습니다.
- **Gemini** 는 무료 티어로 시작할 수 있어 처음 테스트에 좋습니다.
- Claude 키에서 `anthropic-workspace-id is required` 오류가 나면 설정의
  **워크스페이스 ID** 칸을 채우세요(신원 연동 키).

## 5. 산출물

작업대·리포트 화면에서 내려받습니다.

- **진단 결과 보고서(PDF)** — 개요·위험도 표·상세·총평.
- **조치 가이드(PDF)** — 유형별 조치 방법.
- **분석목록표(xlsx)** — 14컬럼 고객 제출용(조치 여부/방법 컬럼 포함).
- **SARIF 2.1.0** — GitHub Code Scanning 업로드, IDE(SARIF Viewer), 다른 도구 연동용.
- **CSV** — 표 형태 원자료.

## 6. CI/CD 연동

GitHub Actions 로 PR·푸시마다 자동 스캔하고 결과를 Code Scanning 에 올릴 수 있습니다.

```yaml
- uses: KimJeju/cpguard@v0.1.2
  with: { path: '.', fail-on: 'high' }   # high 이상 탐지 시 빌드 실패
- if: always()
  uses: github/codeql-action/upload-sarif@v3
  with: { sarif_file: '${{ steps.<id>.outputs.sarif }}' }
```

CLI 로도 됩니다: `cpguard scan . --sarif out.sarif --fail-on high`

## 7. 자주 묻는 것

- **인터넷 없이 되나요?** — 네. 스캔·작업대·산출물 모두 로컬에서 동작합니다.
  LLM 트리아지만 클라우드 API 를 씁니다(선택).
- **큰 프로젝트가 느려요** — 정상입니다. 수만 파일은 수 분 걸립니다. 진행 바로 상태를 봅니다.
- **탐지가 너무 많아요** — 위험도 필터 + LLM 트리아지로 우선순위를 좁히고, 판정으로 정리하세요.
