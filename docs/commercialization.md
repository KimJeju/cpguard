# 상용화 로드맵 (아이디어)

CPGuard 를 졸업작품 → 실제 판매 가능한 제품으로 끌어올리기 위한 작업 목록.
우선순위는 대략 위→아래.

## 시장 현실 (먼저 읽을 것)

아래 기능 목록은 "무엇을 만들 수 있는가"이고, 이 절은 "무엇이 팔리는가"다. 순서가 바뀌면
기능은 늘고 매출은 그대로인 상태가 된다.

### 엔진으로는 이기지 못한다

CPG + taint 엔진의 정면 승부 상대는 Semgrep·CodeQL 이고, 저쪽은 전담 인력이 수년째 붙어
있다. 1인 개발로 엔진 품질만으로 앞서는 것은 현실적이지 않다. LLM 트리아지도 차별점의
수명이 짧다 — 주요 상용 도구가 이미 같은 기능을 붙이고 있다. **엔진은 입장료이지 해자가
아니다.**

현재 OWASP Benchmark 점수(0.392 / F1 0.689)의 해석에도 주의가 필요하다. 이 벤치마크는
**자바 합성 코드**이고, CPGuard 의 자바 규칙은 10종으로 가장 얕다. 오래 다듬은 JS·PHP·
Python 은 이 숫자에 반영되지 않는다. 즉 현재 대표 수치는 가장 약한 영역을 측정한 값이다.

더 중요한 것은 **비교군이 없다**는 점이다. 0.392 가 경쟁력 있는 수치인지 아닌지 판단할
근거가 아직 없다. Semgrep·CodeQL·FindSecBugs 는 모두 무료이고 `bench/owasp_benchmark.py`
하네스에 그대로 물릴 수 있다. 이 비교를 하기 전까지 정확도에 관한 모든 주장은 추측이다.

### 대체 불가능한 것은 따로 있다

1. **한국 컴플라이언스 산출물** — 행안부 소프트웨어 개발보안 가이드 점검표, 전자금융감독규정
   대응, 합본 진단 결과 보고서(최초 검출 → 정오탐 점검 → 최종 조치대상), 14컬럼 분석목록표.
   해외 도구는 이것을 만들지 않으며, 만들 유인도 없다. 국내 진단 시장에서 발주처가 실제로
   받는 산출물은 취약점 목록이 아니라 이 문서들이다.
2. **완전 오프라인 동작** — 에어갭·금융·공공. 클라우드 SaaS 가 들어갈 수 없는 영역.
3. **진단원 워크플로** — 감사 상태, 정오탐 판정 근거, 검토 화면. 도구가 아니라 업무 흐름을
   담고 있다.

이 세 가지는 현업 진단 경험에서 나온 것이고, 경쟁자가 흉내내기 어렵다. 제품의 무게중심을
여기에 두어야 한다.

### 수익 경로와 현실성

| 경로 | 난이도 | 기간 | 평가 |
|---|---|---|---|
| **본인 진단 업무 도구** | 이미 확보 | 즉시 | 산출물 작성 시간 단축 = 원가 절감으로 즉시 회수 |
| **동종 1인 컨설턴트·소형 진단업체 라이선스** | 낮음 | 3~6개월 | 시장 규모는 작지만 실재. 영업 경로가 인맥으로 확보됨 |
| **OSS + 유료 지원·커스텀 룰** | 중간 | 1년 이상 | 채택이 선행되어야 함. 현 단계에서는 순서가 맞지 않음 |
| **제품화·공공조달** | 매우 높음 | 2~3년 | GS인증·조달등록·레퍼런스·법인 필요. 1인 규모로는 불가 |

첫 번째 경로가 가장 저평가되어 있다. 매출이 아니라 원가 절감이라 눈에 띄지 않을 뿐,
회수가 이미 시작될 수 있는 유일한 경로다.

### 최대 리스크: 유지보수 부담 대비 회수

오픈소스 정적 분석기는 규칙 갱신·언어 추가·오탐 신고가 끝없이 유입된다. 사용자가 늘면
이슈 응대만으로 상당한 시간이 든다. 수익 경로가 없는 상태에서 사용자만 늘리면 부담만
증가하고, 그 상태는 대개 1~2년 안에 방치로 끝난다. **수익 경로 검증 전의 대규모 홍보는
이익보다 위험이 크다.**

### 검증 순서

1. **경쟁 도구 벤치마크 비교** — 같은 하네스로 Semgrep·CodeQL·FindSecBugs 측정. 좌표 확보.
2. **본인 진단 업무에 실제 투입** — 산출물이 실무에서 통하는지가 유일하게 중요한 검증.
3. **동종 컨설턴트 3~5명에게 사용 요청** — "구매 의사"가 아니라 "사용 의사"를 본다.
   여기서 반응이 없으면 시장이 없는 것이다.
4. 그 이후에 홍보 — 블로그 기술글 → GeekNews → HN.

## 0. 제품 에디션 전략 (DB 결정과 직결)

| 에디션 | 대상 | DB | 배포 |
|---|---|---|---|
| **Desktop (Local)** | 1인 진단자·컨설턴트 | **SQLite(내장)** | 오프라인 설치본(현재) |
| **Team / Server** | 팀·기업 내부망 | **PostgreSQL** | Docker/서비스, 중앙 서버 + 웹 |
| **CI / SaaS** | DevSecOps 파이프라인 | PostgreSQL(+객체스토리지) | 클라우드/온프렘 |

- PostgreSQL 은 **Team/Server 부터** 도입(동시 다중 사용자·중앙 저장). Desktop 은 SQLite 유지.
- 이미 `CPGUARD_DATABASE_URL` 로 Postgres 전환 가능 → 서버 에디션의 토대는 놓임.

## 1. 정확도 · 엔진 (제품의 핵심 가치)

- **언어 확장**: Java/Kotlin·C#·Go 어댑터(수요 큰 순). 현재 JS/TS/PHP/Python.
- **프레임워크 인지**: Spring·Django·Express·Laravel 의 라우팅/ORM/템플릿을 이해해
  source(요청)·sink(응답/쿼리) 를 정확히 잡기.
- **정확도 벤치마크 공개**: OWASP Benchmark·Juliet·CVE 재현 세트로 정밀도/재현율 수치화.
  상용 정적 진단 도구 대비 오탐률을 **숫자로** 보여주는 게 세일즈의 핵심.
- **경로/도달성 정밀화**: sanitizer·검증 함수 인식 강화, 프레임워크 미들웨어 반영.

## 2. 확장성 · 성능 (대규모 고객 대응)

- `docs/large-scale.md` 6종(싱크필터·FindingDB·집계API·파싱캐시·멀티프로세스·트리아지클러스터) 완료.
- 다음: **증분 스캔 정식화**(요약 캐시까지), **분산 스캔**(워커 여러 대), **CPG 온디스크**.

## 3. 통합 · 워크플로우 (팀 도입의 관문)

- **CI/CD 통합**: GitHub Actions·GitLab CI·Jenkins 플러그인. PR 코멘트로 신규 취약점 표시,
  기준 미달 시 빌드 실패(SARIF 업로드 → GitHub Code Scanning 연동).
- **이슈 트래커 연동**: Jira·GitHub Issues 자동 티켓 생성(조치 추적).
- **Git 인지**: 커밋·PR 단위 diff 스캔, blame 으로 도입 커밋·담당자 표시.
- **Webhook·API**: 스캔 트리거·결과 조회 REST API 정식화.

## 4. 협업 · 거버넌스 (기업 필수)

- **멀티 유저·RBAC**: 로그인·역할(관리자/진단자/뷰어)·프로젝트 권한.
- **감사 이력**: 누가 언제 무엇을 confirmed/FP 했는지 audit log(규제 대응).
- **정책·베이스라인**: 기존 이슈 baseline, 신규만 게이트, 억제(suppress) 규칙 관리.
- **SSO**: SAML/OIDC(기업 판매 시 요구됨).

## 5. 리포트 · 컴플라이언스 (구매 결정 요인)

- 이미: 진단 결과 보고서·조치 가이드 PDF. 다음:
- **표준 매핑**: OWASP Top 10·CWE Top 25·PCI-DSS·ISO 27001·전자금융감독규정 매핑 리포트.
- **경영진 요약 대시보드**: 추세·위험 점수·조치율 KPI.
- **커스텀 브랜딩**: 고객사 로고·표지 템플릿(컨설팅사 리셀 대응).

## 6. LLM 트리아지 고도화 (차별점)

- **비용 통제**: 클러스터링(완료)·캐시·모델 선택(완료). 다음: 로컬/온프렘 LLM 옵션
  (에어갭 고객은 클라우드 LLM 못 씀 → Ollama·vLLM 연동).
- **근거 신뢰도**: 트리아지 판정에 코드 인용·재현 조건 첨부, 사람 검토 루프.

## 7. 배포 · 운영 · 라이선스 (판매 실무)

- **라이선스 모델**: 좌석/스캔량/코드 규모 기반. 라이선스 키·활성화.
- **자동 업데이트**: 룰·엔진 업데이트 채널(설치본 재배포 대신 델타).
- **Docker/Helm**: 서버 에디션 원클릭 배포. 온프렘 설치 가이드.
- **텔레메트리(옵트인)**: 크래시·성능 리포트(개인정보/코드는 절대 미전송 — 신뢰가 곧 제품).
- **코드 서명**: 설치본 인증서 서명(SmartScreen·백신 신뢰).

## 8. 신뢰 · 보안 (보안 제품의 자기 신뢰)

- 자체 코드 분석/의존성 감사·SBOM 공개, 취약점 신고 창구(security.txt).
- 스캔 대상 코드·시크릿을 **로컬에서만** 처리(현재 원칙 유지) — 세일즈 포인트로 명문화.
- 3자 침투테스트·인증(가능하면 CREST/공인).

## 지금 바로 할 만한 3가지 (ROI 높은 순)

이전 목록(GitHub Action · Java 어댑터 · 정확도 벤치마크 공개)은 v0.1.4 기준으로 모두 완료됐다.

1. **경쟁 도구 벤치마크 비교** — Semgrep·CodeQL·FindSecBugs 를 같은 하네스로 측정.
   정확도 주장의 근거이자, 엔진 개선 우선순위를 정하는 좌표.
2. **실무 투입 검증** — 실제 진단 프로젝트에서 산출물을 그대로 제출해 본다.
   여기서 나오는 수정 요구가 다른 어떤 기능보다 우선한다.
3. **동종 컨설턴트 대상 사용 요청** — 3~5명. 시장 존재 여부를 가장 싸게 확인하는 방법.
